# 从模型工程到 RL 和 sim-to-real

本工程完成的是资产整理、Humble 运行入口、主机配置记录以及后续接口准备。训练任务尚未定义，因此没有虚构训练奖励或提供看似能训练、实际物理模型未通过的训练脚本。

## 推荐先做的事情

1. 在目标 Ubuntu 上运行 check、build、display，确认安装件、机械臂、五指和联动正确。
2. 运行 gpu-info，补充完整 GPU 名称；现有报告只有被截断的 NVIDIA GeForce 名称，不能推断具体型号或是否具备 RT 核心。
3. 可选安装 MuJoCo 隔离环境，运行 CPU 检查，复现/核对腕部凸包交叠。
4. 为训练选择任务：例如固定机械臂下的手部开合、机械臂到达、抓取或在手操作。任务不同，动作维度、接触要求和奖励都不同。

## 训练前需要解决

- 腕部 link5/link7 的约 8 mm 凸包接触：查明源网格和装配关系，制作并记录适合 MuJoCo 的碰撞几何，检查有限姿态、过渡及随机采样。应优先合理分解/修正碰撞几何，不能简单删除碰撞体或增加忽略对来宣称通过。
- 原 SRDF 已有 31 对装配碰撞豁免，部分指尖/基座没有独立碰撞体；抓取任务需核实实际接触几何，而非只看外观。
- 已交付仿真含零重力设置。训练前要按任务选择固定基座、重力、初值及接触场景，并验证重力和驱动下的稳定性。不能把旧零重力演示当作真实重力验收。
- 位置执行器增益、力矩、速度、质量惯量、摩擦、延迟和传感器噪声需对照实物。现有数值是模型字段，尚未经实测标定。
- 实现环境的 reset/step、观测、动作、奖励、终止条件、控制周期、随机种子、数据记录及评估。根据任务决定是否只训练手部 10 维、机械臂 7 维或组合 17 维；当前接口记录的是组合模型全部独立关节。

## 已准备的坐标接口

`config/policy_contract.json` 明确 17 个独立关节的顺序、23 个状态关节的顺序、六个联动关系，以及有效位置/速度范围。`scripts/policy_interface.py` 提供纯数学的按名称展开与归一化映射，不发送 ROS 或硬件命令。

归一化示例将 [-1,1] 映射为关节有效绝对位置范围；零动作是范围中点，不是闭合姿态或实机停止。它只是可复用的坐标工具，不是已批准的训练控制方案。实际训练常需更小的增量动作、速率限制、滤波和任务相关关节子集。

17 维独立输入和 23 维全状态不能混用。MuJoCo、PhysX 和实机驱动可能各有不同关节顺序，适配器应按名称映射。手部十个主动关节与实际电机编号、方向、减速比和协议尚未建立映射。

## 仿真到实物

先完成仿真稳定性、随机种子评估和参数敏感性实验，再用测量结果设置域随机化。实机接口应单独实现单位/符号/零位校准、状态时间戳、控制周期、命令边界和故障处理，并先做受限回放和低幅度测试。

当前默认展示入口继承 AF_CAN 禁止过滤器，不含真实控制后端。后续实机部署应采用独立的已审阅入口，不能直接把模型姿态播放器当作硬件控制器。

待确定的信息：首个任务、实际机械臂与手部型号/固件、现有驱动工程、控制接口和周期、是否使用触觉/相机，以及本机训练还是使用更强的训练设备。本阶段不需要这些信息也能先完成模型展示和 CPU 检查。
