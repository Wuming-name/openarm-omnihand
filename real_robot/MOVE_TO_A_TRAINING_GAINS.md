# 用训练原始参数到 A

> 已被 `NATIVE_MIT_OFFICIAL.md` 替代。本文件下文为历史外环调试记录。
> 当前 move_to_a.py 默认使用完整 MIT＋官方 V1.0 增益，旧 --j5-kd/--j6-kd 选项已移除。

## 当前生效参数：J5 和 J6 均降低外环 Kd

J5 在 to_A 段出现增长振荡后，仅将 J5 主机外环 Kd 从 3.0 降到 0.5，Kp=30 保持；J6 继续 Kp=25、Kd=0.5。其他轴、模型、轨迹及保护不改。不修改电机内环、不修改保存的训练配置或 PPO 文件。下文先前的 J6 单轴覆盖说明为历史记录，以本节为准。

| 轴 | 外环 Kp (Nm/rad) | 外环 Kd (Nm·s/rad) | 峰值力矩上限 (Nm) | 连续力矩阈值 (Nm) |
|---|---:|---:|---:|---:|
| J1 | 100 | 10 | 40 | 20 |
| J2 | 120 | 12 | 40 | 20 |
| J3 | 80 | 8 | 27 | 9 |
| J4 | 80 | 8 | 27 | 9 |
| J5 | 30 | 0.5 | 7 | 3 |
| J6 | 25 | 0.5 | 7 | 3 |
| J7 | 20 | 2 | 7 | 3 |

表中 Kp/Kd 适用于本次训练配置与 move_to_a.py 的默认覆盖，不代表策略训练文件已同步修改。总力矩仍受训练和硬件两者中更小的上限约束，超过连续额定力矩 0.5秒会停止。MIT 原生 Kp=0、Kd=0，力矩由主机计算，重力补偿保持原样。降低阻尼是诊断候选，软件测试不代表实机已稳定。

```bash
python -m real_robot.move_to_a --run outputs/ppo/run_20261028_164711_538719 --j5-kd 0.5 --j6-kd 0.5 --execute
```

报告 kp/kd 为实际使用参数，training_kd 为保存的原值，并记录 j5_outer_kd_override/j6_outer_kd_override。两个选项默认都是 0.5；旧值只为表达基线保留，不建议在已观察到振荡后重新执行。

## J6 外环阻尼修正

原始参数实机测试中，J6 在固定目标时出现增长振荡并触发 1rad/s 超速保护。根据用户要求，本次只将 J6 主机外环 Kd 从 2.5 降到 0.5，Kp=25 不变；其他六轴、重力补偿、轨迹及保护不变。没有引入电机内环阻尼，MIT 原生 Kp/Kd 仍为零。此参数是诊断候选，尚未验证实机稳定性。

`--j6-kd 0.5` 为新默认值，报告中的 kd 是实际控制值，training_kd 记录保存的原始值；训练文件、哈希和模型不修改。下文描述的训练原始参数是基线；当前运行仅有这一项覆盖，不能再称七轴全部未改。`--j6-kd 2.5` 可表达旧值，但已出现发散趋势，暂不重复运行旧值。

Ubuntu 本次最后一条执行命令：

```bash
python -m real_robot.move_to_a --run outputs/ppo/run_20261028_164711_538719 --j6-kd 0.5 --execute
```

`move_to_a.py` 是独立的 SocketCAN 调试入口。它共用 ROS2 底层 `Servo` 的 PD、力矩限制和看门狗计算，但此测试不经过 ROS2 话题，不启动 PPO，不操作 can1 手部。

固定使用保存训练配置的原始参数，增益比例为 1.0：Kp=[100,120,80,80,30,25,20]，Kd=[10,12,8,8,3,2.5,2]（实际值从本次训练目录加载并记录）。重力/偏置补偿也使用相同模型及配置。主机计算总力矩，发送 MIT 的力矩命令，电机原生 Kp/Kd 设为零；不能把这些 Kd 直接写入电机原生字段。

流程：读取新 probe → 离线筛选三段路径 → 使能前重新读取并检查新计划匹配 → 保持起始姿态 1 秒 → J2 退离 → J6 退离 → 平滑到 A → 保持 A。没有返回原位步骤，也没有中途逐轴 0.02rad 精度验收。轨迹仍采用已筛选的慢速参考，参数不逐步增加。完整路径、端点、时长和训练哈希在程序内部再次验证，不能只修改计划 JSON 让程序执行任意路径。

A 验收：各轴距训练 q_A 不超过 0.01rad，模型计算的手掌距 A 不超过 0.015m，反馈速度不超过 0.05rad/s，连续保持 0.5秒。末端坐标来自模型前向运动学，尚非外部实测位置。轨迹结束后最多等待 15秒；未到位则报告失败。到位后打印 `A_REACHED` 并持续保持，直到操作者 Ctrl+C。到位后脱离验收区域会报告故障。其他阶段只有名称和最终报告，原始数据记录在最后约两秒的轨迹文件。

仍保留：电机 ID/MIT 编码核对、七轴状态/温度/反馈新鲜度、硬限位、危险超速（hardware.json）、总力矩限幅和持续额定力矩保护、控制器 20ms 间隔保护、100ms 上层参考新鲜度、共享 Servo 的大幅目标领先限制。退离期间仅允许原已知接触在初始深度+0.5mm范围内；进入到 A 段后使用原模型的严格接触规则。普通小误差不再中断，但严重落后仍会触发共享控制器的大幅目标领先保护。

此程序不修改电机 TIMEOUT，不宣称电机通信超时或完整 ROS2 校准已验证。初始七轴均须未使能。任何正常/异常退出均尝试失能，无法保证失能送达；失能会失去主动承重，机械臂可能下落。必须有不阻碍运动的可靠机械支撑和独立停止措施。到位后先承托机械臂再 Ctrl+C，不能在悬空承重时直接结束程序。不要同时运行另一个机械臂控制器。

Ubuntu 无硬件预览：

```bash
python -m real_robot.probe &&
python -m real_robot.plan_startup --run outputs/ppo/run_20261028_164711_538719 &&
python -m real_robot.move_to_a --run outputs/ppo/run_20261028_164711_538719
```

执行时在最后一条命令添加 `--execute`。默认无 CAN，默认预览的 passed=false 表示没有进行实物到位验收，preview_only=true 且无 error 才表示几何预览完成。
