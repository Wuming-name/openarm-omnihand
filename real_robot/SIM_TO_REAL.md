## 第一阶段：500Hz主机PD与MIT力矩链

退出所有其他机械臂控制程序，保持手部现状。**机械臂全程需要可靠支撑；该测试结束、检测异常或Ctrl+C后，会向七轴逐一尝试发送失能。失能后不能支撑机械臂，通信故障也可能使失能发送失败。** 不要依靠停止发送或未验证的TIMEOUT保证停止。测试不接管已使能电机，须七轴最初均未使能。

Ubuntu在既有训练虚拟环境中执行：

```bash
cd /home/lsk/openarm_v1_ws/src/openarm-omnihand-project
source .venv-ppo/bin/activate

# 本机仿真检查，不打开CAN；该频率是仿真时钟，不是实机时序证明
python -m real_robot.commission_hold \
  --run outputs/ppo/run_20261028_164711_538719 --seconds 3

# 有支撑的实机测试：当前位置保持3秒，然后尝试失能
python -m real_robot.commission_hold \
  --run outputs/ppo/run_20261028_164711_538719 \
  --backend socketcan --execute --seconds 3
```

目标为启动时读取的七轴位置，采用保存任务中的Kp/Kd，主机500Hz计算PD；20ms更新名义模型bias前馈，500Hz通过MIT Kp=Kd=0的力矩通道发送总力矩，沿用训练/机械峰值限幅与持续力矩保护。测试不加载PPO权重，不前往A/B，不发送手部指令。

模型硬限位、自碰撞和初始反馈检查在使能前执行。运行时位置偏差超过0.05rad、速度超过0.15rad/s、反馈超过50ms未更新、主机不能跟上2ms节拍或持续力矩超限均会结束测试。整体反馈更新验收要求每轴至少在80%的控制周期观测到新反馈，循环平均频率不低于475Hz。这只是短时验收指标，不是硬实时保证；ROS2传输尚不在此测试内。

报告保存在`outputs/real_robot/*_commission_hold.json`，包含目标、增益、最大偏差、最大指令力矩、循环频率/最大间隔、每轴观测到的新反馈次数以及失能发送结果。`sent=true`只代表发送调用成功，不代表电机实际收到并失能。正常mock报告的`timing_clock=simulation`；实机为`monotonic`。

本阶段采用用户授权的有支撑、限时测试，不要求填写完整部署的标定确认字段，也不将任何未核实项目改为已验证。现有完整ROS2实机入口的标定检查保留。后续根据报告再进行慢速到A以及ROS2/PPO阶段。
