# PPO 训练代码与实现说明

## 一、对应的任务

OpenArm V1 七轴携带 OmniHand，手部在一个固定握拳姿态下作为负载；控制手掌 TCP 从 A 到 B。第一版奖励兼顾位置到达、停止稳定、朝向和平滑性。不涉及抓取物体、触觉操作，也不训练手指。

实机预期顺序是：机械臂保持当前位置 → 手部握合并确认 → 传统控制移动至 A → 平滑交给 RL → 到 B 后保持。这里实现的是该流程中 **RL 仿真训练与评估部分**。代码没有向 ROS 发布消息，不操作 CAN，也不负责实机上电。

## 二、目录和每个文件的职责

| 文件 | 用途 | 主要输入与输出 |
|---|---|---|
| `__init__.py` | 将目录定义为 Python 包，支持 `python -m rl_ppo.xxx` | 不连接设备 |
| `requirements.txt` | 固定运行依赖，避免改变既有 ROS Python | NumPy、MuJoCo、Gymnasium、SB3、PyTorch |
| `COLCON_IGNORE` | 告诉 colcon 不在这里搜索 ROS 包 | 不影响已有 description 包 |
| `.gitignore` | 保证派生碰撞 OBJ 纳入 Git，忽略 Python 缓存 | 训练输出使用工程根目录已有忽略规则 |
| `configs/reach.json` | 唯一默认实验配置 | 模型路径、固定手姿、TCP、控制、奖励、随机化、PPO 参数 |
| `common.py` | 统一路径、JSON、SHA256、配置验证、关节顺序和观测字段 | 配置字典、文件指纹 |
| `model.py` | 将源展示模型转换成训练模型 | 源 MJCF → 固定手部、启用重力、七轴力矩执行器、TCP site、模型清单 |
| `assets/wrist/manifest.json` | 记录两处腕部碰撞网格的来源、拆分方法和哈希 | 与源网格不匹配时拒绝构建 |
| `assets/wrist/*.obj` | 两处腕部网格的连通部件 | 每个部件分别参与凸包碰撞，避免凸包跨越不相连的部件；没有增加碰撞排除对 |
| `decompose.py` | 可选离线工具，重新生成碰撞部件 | 默认 trimesh 连通部件拆分，可选 CoACD 进一步凸分解，日常训练不调用 |
| `prepare.py` | 创建可重复的 A/B 仿真任务并预检 | 输出 task.json、模型、配置副本与模型 manifest |

| `train.py` | 启动 PPO、多环境、课程学习、评估及检查点 | 输入预检通过的任务，输出完整实验目录和权重 |
| `evaluate.py` | 加载模型独立评估，禁止偷偷更换任务/配置 | 成功率、误差、失败原因、首回合轨迹，可显示动作 |
| `inspect_task.py` | 查看 A/B，或使用传统关节参考控制检查可执行性 | 几何信息、仿真参考控制报告 |
| `verify.py` | 对真实 MuJoCo 环境进行接口与行为检查 | 环境检查报告 verification.json |
| `tests/test_contract.py` | 测试观测约定、配置校验、旋转计算、Python 3.10 语法 | 离线 unittest，不连接硬件 |
| `VALIDATION.json` | 记录本次作者环境中实际完成的验证与未验证范围 | Windows Python 3.11 的结果，不冒充 Ubuntu 或实机验收 |
| `README.md` | 从安装到训练和评估的操作入口 | Ubuntu 命令与 Git 同步步骤 |
| `代码与训练说明.md` | 本文：实现逻辑、边界及各个文件解释 | 供后续修改、审查和部署对接 |

## 三、model.py 为什么要修改展示模型

源文件为 `model/simulation/mjcf/openarm_omnihand.xml`，只读使用，源码不覆盖。

### 3.1 冻结手部，而不是删掉手部

源模型有 23 个运动坐标、17 个执行器。构建时先把 16 个手部运动坐标设为配置的固定角度，计算每个手部刚体的实际相对位姿，然后去掉对应运动关节和 mimic 等式，把这些位姿写为固定变换。保留刚体质量、惯量、视觉和碰撞几何。

这样得到 `nq=nv=nu=7` 的机械臂训练模型。构建后比较冻结前后的所有刚体变换，不一致就失败，避免手指折叠后变形或负载被删掉。

默认手姿是根据官方 SDK 1.1.10 右手 FIST1 求解器离线得到的候选弧度值，来源提交 `1b552ea77c2d61adef327d179dc9f6b47405c628`。它与实机当前“六轴握合、四轴保持”的姿态还未完全对应；训练前应完成实机验证，再替换 `hand_pose_rad`。它不是原始电机计数，也没有使用 `count/4096` 直接作为弧度。

### 3.2 处理腕部网格的整体凸包问题

原报告存在 link5/link7 约 8 mm 穿透。检查发现两处源碰撞网格分别包含 4 个和 17 个不相连的连通部件。把它们合成一个整体凸包会跨越部件之间的间隙。附带资产按连通部件拆开，保留每个部件原来的三角形；MuJoCo 对每个部件分别使用凸包。其他碰撞网格、源排除对保持原样，没有新增碰撞排除对或全局禁用自碰撞。不是整体凹形网格的精确碰撞，单个部件的凹陷仍可能被其凸包填平。

其中 link7 的 3 个部件为独立平面补片，无法单独形成三维凸包；生成时把这些补片的原三角形并入最近的立体部件，最终为 link5 的 4 件和 link7 的 14 件。没有删除平面几何，也没有人为缩小碰撞网格。

这些仍是近似碰撞几何，需要目视核对。文件哈希确认凸块来自当前源网格，但哈希不能证明几何一定与实物精确一致。若模型修改导致来源哈希不一致，程序会拒绝构建。

重做连通拆分时，在隔离环境安装 `trimesh==4.7.4`，执行 `python -m rl_ppo.decompose --output 新目录`。若需要进一步凸分解，再安装 `coacd==1.0.7` 并增加 `--method coacd`，此操作可能很慢。检查后更新 assets/wrist，不要未经检查替换原模型碰撞文件。

### 3.3 重力与力矩模型

源 MJCF 的重力为零，原位置增益用于展示，不能拿来代表达妙电机实测参数。训练模型启用世界坐标系的 `[0,0,-9.81]` 重力，七轴使用 motor 执行器，总输出力矩由环境计算和裁剪。

控制器模拟 MIT 形式：

```text
tau = Kp * (q_cmd - q) + Kd * (v_cmd - qdot) + nominal_bias_feedforward
tau = clip(tau, -torque_limit, torque_limit)
```

前馈由未随机化的名义模型计算，包含重力及速度相关偏置。随机化真实质量时不会用随机化模型的“真值”来完美补偿。前馈每个策略周期计算，物理子步中保持。实机需要驱动支持并验证对应的前馈实现。

Kp/Kd、力矩上限、摩擦和 armature 是可配置的仿真初值，不是各型号电机的最终标定结果。总力矩裁剪包含前馈，避免在执行器限幅之外额外施加无限补偿力。

## 四、prepare.py 怎样确定 A 和 B

1. 生成模型并检查七轴结构。
2. 使用固定随机种子，在软限位内采样关节姿态 q_A。
3. 拒绝有超过 1 mm 穿透的姿态，拒绝 TCP 超出配置工作范围的姿态。
4. 从 q_A 附近采样 q_B，用正运动学得到 A/B 的掌心位置。
5. 要求两点相距 20～30 cm，朝向差不超过 0.45 rad。
6. 检查 q_A→q_B 之间 40 个插值姿态，要求工作范围和自碰撞检查通过。
7. 用名义动力学在 A 保持 2 秒，要求没有失败、关节漂移不超过 0.02 rad。
8. 全部通过才写入 `preflight_passed: true`，训练入口拒绝未经预检的任务。

A/B 是自动选出的 **仿真候选**，不是实机已验证目标。40 点检查是离散采样，不能替代连续碰撞检测，也不能保证 PPO 学到的任意路径没有碰撞；实际训练每个物理子步仍检测碰撞。程序不会自动把这些关节值发给电机。

掌心 TCP 为 `omni_R_palm` site 加固定偏移，默认 `[0,0.045,0]` 米是便于观察的候选掌心参考点，未进行实物测量。位置和目标统一转换到 `openarm_body_link0` site 坐标系。修改 TCP、手姿、增益或其他配置后，要用新的目录重新 prepare，再重新训练，不能混用旧权重。

## 五、env.py 的观测、动作与物理时序

### 5.1 37 维输入的准确顺序

| 索引 | 内容 | 归一化 |
|---|---|---|
| 0～6 | 实际关节位置 q | 软限位中点/半跨度 |
| 7～13 | 实际关节速度 | 除以各轴 vmax |
| 14～20 | q_cmd − q | 除以目标领先上限 0.20 rad |
| 21～23 | 基座坐标系掌心 TCP 位置 | 除以 position_scale_m |
| 24～26 | 目标位置 − 当前 TCP 位置 | 除以 goal_scale_m |
| 27～29 | 目标朝向相对当前朝向的旋转向量 | 除以 π |
| 30～36 | 上次采用的关节速度命令 | 除以各轴 vmax |

关节顺序严格为 `openarm_right_joint1` 到 `openarm_right_joint7`。旋转误差使用旋转矩阵/四元数转换，不直接相减欧拉角。

启用测量噪声时，q、qdot 与 TCP 正运动学使用同一组带噪声状态，避免策略看到实机无法获取的精确 TCP 真值。奖励和成功判定使用仿真真值。没有在线 VecNormalize，全部缩放规则随配置与 policy_contract 保存，部署必须完整复现。

### 5.2 7 维输出

动作范围 `[-1,1]^7`，表示归一化期望关节速度。先乘 vmax，再限制加速度，积分得到 q_cmd，之后限制目标领先量和软关节限位。环境保留 q_cmd 与上次速度命令状态，观测中也包含这两种状态的信息。

默认策略周期 0.02 秒，物理步长 0.002 秒，即每个动作执行 10 个物理子步。策略不是每步直接设 qpos，不会把机械臂瞬移到目标，也不直接输出未限幅力矩。

### 5.3 奖励

奖励包含到目标的距离进展、剩余距离、朝向误差、关节速度、速度命令变化、归一化力矩和时间成本。持续到达时奖励 success_bonus，碰撞/限位等失败时扣 failure_penalty。除距离进展和终止奖励之外，运行成本乘策略周期，降低改变控制频率时奖励尺度漂移。

### 5.4 成功与终止

连续 0.5 秒满足：距离小于 2 cm、末端速度小于 0.03 m/s、朝向误差小于 0.25 rad，才算成功。自碰撞、工作范围越界、关节越界、超过 3 rad/s 的异常速度或过大跟踪误差终止回合。12 秒仍未成功则为时间截断，供 PPO 正确处理 bootstrap。

非有限值或 MuJoCo 因数值失稳自动重置时直接中止训练，不让策略把数值异常当作正常回合。

### 5.5 随机化

默认每回合随机质量/惯量 ±5%、增益 ±5%、阻尼 ±10%，并添加小幅编码器位置/速度噪声。每次都从名义参数开始，不累计漂移。当前没有实现通信丢包、CAN 延迟或传动间隙；后续需根据实际测量添加，而不是宣称已经消除 sim-to-real 差距。

## 六、train.py 的训练逻辑

训练先读取预检通过的任务，校验模型和配置；创建全新输出目录，把任务、模型、配置以及当前 Python 源文件副本放入该目录，避免后续修改源码后无法追溯实验。

默认 PPO：CPU、2 个并行环境、两层 128 单元 actor/critic、学习率 3e-4、rollout 1024、batch 256、gamma 0.99、GAE 0.95、clip 0.2、entropy coefficient 0.005。进程采用 spawn，入口有 main guard。

课程目标最初位于 q_A→q_B 插值的 25% 处，训练前 40% 步数内逐渐移动到完整 B。课程参数只在下一次 reset 生效，不在同一回合突然移动目标。每个课程目标都通过正运动学计算，来源是已检查的连接姿态区间。重置始终在 A 附近添加小扰动。

定期评估固定使用完整 B，不参与训练更新。定期保存检查点和最佳模型。正常完成保存 final_model.zip，Ctrl+C 保存 interrupted_model.zip，其他异常标记 failed 并保存 failed_model.zip；这些名字都不代表模型学会任务，需要独立评估。

第一版训练分布是当前固定 A/B 及 A 附近的小扰动，不覆盖任意目标点。输入虽然包含目标误差，也不能据此宣称模型已经泛化到任意 B。要扩展工作空间，需要采样更多可达目标并重新训练/评估。

## 七、输出文件在哪里

```text
outputs/ppo/
  task/
    model.xml                 训练模型可读版本，含生成时本机资产路径
    model.mjb                 自包含二进制模型，供当前固定版本 MuJoCo 加载
    model.manifest.json       来源、凸分解、冻结检查、配置及模型哈希
    config.json               本任务参数副本
    task.json                 A/B、参考关节姿态、预检结果和版本
    verification.json         verify 结果
    baseline_*.json           传统参考控制诊断
  run_时间戳/
    task/                     本次实验的完整任务副本
    code_snapshot/            本次实验的 Python 源码副本
    training_settings.json    生效步数、并行数、随机种子、依赖版本、配置
    policy_contract.json      观测/动作约定及任务/模型/配置哈希
    logs/progress.csv         PPO 训练指标
    checkpoints/              定期权重
    best/best_model.zip       定期评估选出的模型（需达到评估间隔才出现）
    final_model.zip           正常训练结束权重
    result.json               最后权重名、实际训练步数与中断/失败标记
    evaluation_*.json         独立评估报告
    evaluation_*_trajectory.json  首回合轨迹
```

这些内容均在工程已有忽略目录中。正常双机协作仅提交 rl_ppo 源码与小型凸块资产；Ubuntu 生成自己的模型和输出。不要把 Windows 生成的含本机路径的 XML 当成 Ubuntu 源模型使用。MJB 使用固定 MuJoCo 版本加载，跨平台迁移实验前仍应重新验证。

## 八、verify.py 与测试分别证明什么

unittest 检查协议尺寸、配置拒绝、旋转计算、配置哈希和 Python 3.10 语法。verify 则真正加载模型，执行 SB3 check_env、重置复现、静态保持、随机动作约束、随机化复现及带扰动保持。

baseline 检查传统关节参考在同一受限控制器下能否到达 B，帮助区分“环境/控制模型错误”与“RL 尚未学会”。短程 PPO 测试只验证采样、优化、保存、重新加载及评估链路，不能作为训练成功率证明。

## 九、实机对接前仍缺少什么

1. 六轴握合的实机结果、四轴保持后的实际固定拳形，以及对应弧度映射。
2. 掌心 TCP 安装偏移、七轴零点和正运动学标定。
3. 七个达妙电机的 CAN ID、MIT 范围、实际增益/力矩限幅、反馈单位、控制频率及延迟。
4. 对腕部碰撞分解、手部外形、质量重心的现场核验。
5. ROS 2 硬件驱动和状态机、至 A 的传统轨迹、无跳变接管、握拳保持监测、状态超时和异常停止。

因此所有任务与结果均标记 `hardware_ready: false`。四周空旷不取消自碰撞、关节限位、负载和通信保护。
